# Scheduled Tasks

A scheduled task starts a new Pi session and sends a prompt at the configured time. Open the scheduler from the session sidebar.

## Create a task in Piarium

Choose a project, add a task, then select a daily, weekly, one-time, or cron schedule. Choose the Pi provider, model, and thinking level, and enter the prompt or slash command. **Run now** starts the same task immediately. **Run as goal** starts a Pi session goal for work that should continue beyond one reply.

## Define a loop in Markdown

A loop is a portable scheduled task whose definition is a Markdown file. Place it in the current project’s `.agents/loops/` directory, or in `~/.agents/loops/` for all projects:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: openai-codex/gpt-5.3-codex
thinking: high
agent: reviewer
timezone: Asia/Shanghai
run_as_goal: true
goal_token_budget: 25000
---
Summarize repository changes since yesterday.
```

The file is the authoritative definition. Piarium’s task list edits that Markdown directly, writes the enabled toggle back to frontmatter, and deletes the file only after confirmation. If an agent or another editor changes the file while the editor is open, saving reports a revision conflict rather than overwriting it.

`name`, `schedule`, `model`, and the Markdown body are required. `model` uses `provider/model`. `enabled` defaults to `false`, so a repository cannot start unattended model runs merely because it was cloned or pulled. `thinking`, `agent`, `timezone`, `run_as_goal`, and `goal_token_budget` are optional Pi fields. Loop files use cron schedules; the GUI also supports daily, weekly, and one-time schedules.

Piarium checks the nearest project directory first, then its ancestors up to the Git worktree root, then the user directory. A higher-priority loop with the same name shadows lower definitions. If a file is temporarily invalid during editing or conflict resolution, its last valid task and runtime history remain available and the parse error is shown. Renaming a loop in frontmatter keeps that history, and Piarium cleans up obsolete duplicate projections left by older versions. Removing the file removes only its loop task; an ordinary GUI task with the same name is never taken over.

Tasks run only while the Piarium server is running. Runtime history—last run, next run, result, duration, and created Pi session—stays in Piarium’s project state and is not written into the Markdown file.
